# exp04：只看 assistant 段，自检能不能分开"完好"与"丢了 / 错了上下文"

起因：exp03——这个模型对 user / system / 工具文本的逐位预测没被训练过（总想结束这条消息），整段打分与上下文好坏反相关。
模型被训练去预测的只有 assistant 段。一个 agent 步的未缓存段里常有 assistant 段（上一步它自己写的调用 / 回答）。

## 设计
历史：user 给出发布计划（26 个自造代号 + 周次）→ assistant "Noted" → user 一段无关闲话（让 256 边界的恢复点落在计划之后）→ assistant "OK"。
新一轮（未缓存段）：user "把计划列出来" → **assistant 逐行 `codename: week N`（只有从历史才能预测）** → user "Thanks"。
逐位打分按"被预测的 token 属于哪个角色的消息"分开：assistant / 其它。
变体：intact；C1 递归状态清零；C3 全部清零；C4 **换成另一份计划的状态**（同结构、代号和周次不同——"恢复了错的对话"）。
每种 2 次（不同 nonce）。

## 预期（跑前写）
- intact 的 assistant 段 surprise 均值低（< 0.5：逐行抄历史）。把握：中高。
- C3、C4 的 assistant 段均值高得多（> 2）：代号和周次只能猜。把握：中高。C1 居中（全注意力层还能抄）。把握：中。
- "其它"角色段：与上下文好坏关系弱或反向（exp03）。把握：中。
- 若 assistant 段分得开，自检就改成只打 assistant 段（设计要 owner 裁）。

## 结果（m3u，27B-4bit，kv16；`raw/run1.txt` 两轮，`raw/itest-*.txt` 走 lmk 的 `check_targets` 全链路）
assistant 段的 surprise 均值（nats/token，约 300 个 token）：

| | exp04 #0 | exp04 #1 | itest 不带草稿 | itest dflash2 |
|---|---|---|---|---|
| intact | 0.109 | 0.111 | 0.090 | 0.096 |
| C1 递归状态清零 | 0.103 | 0.102 | — | — |
| C3 / wiped 全部清零 | 1.331 | 1.302 | 1.315 | 1.337 |
| C4 / wrong 换成另一份计划 | 1.122 | 1.114 | 1.106 | 1.106 |

"其它"角色（user / 模板）在同一批请求里：intact 4.9–5.6，C1 2.0，C3 2.5–2.8，C4 4.8–5.7——不分好坏，C1/C3 还更低（exp03 的现象）。

- 预期对了：intact < 0.5，C3/C4 远高于 intact（约 10 倍）。数值比预期的"> 2"低：代号的前缀（`amber`…）和 `: week` 格式在错的上下文里也猜得中。
- **C1 看不见**：只清递归状态时 assistant 段也是 0.10——全注意力层（每 4 层 1 层）单靠 KV 就能把表抄出来。所以"递归状态坏了"这一种故障
  本身未必造成失忆，也不会被这个检查看到；它能看到的是"模型答不出历史里的东西"。
- 开销：约 300 个位置 52 ms（≈ 175 ms / 1k），段 388 的 prefill 约 1.3 s，≈ 4%。
- 设计因此改为：lmk 把 prompt 里 assistant 段的 token 下标交给引擎（`check_targets`，最近 512 个），引擎只打这些位置；
  没有已知回合标记的家族或带图请求退回打段尾。**这是对已批设计的修改，待 owner 裁。**
