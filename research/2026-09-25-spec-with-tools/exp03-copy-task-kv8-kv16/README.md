# exp03：复述型工具调用（照抄一段文本写文件）开/关草稿，kv8 与 kv16

日期 2026-09-25。m3u。fork e053a72。`../exp01-tools-draft-sha/run.py`，`TASK=copy`（用户给一段 release checklist，要求原样写进 RELEASE.md 再 cat）；
`KV_BITS=8`（推荐组合）与 `KV_BITS=16` 各一次，原始输出 `raw-kv8/`、`raw-kv16/`。

## 为什么
exp01/exp02 的 fizzbuzz 在思考段落在一个 bf16 一 ulp 的平手上（exp02 `raw/margin.txt`：`'\n\n'` 24.125 对 `'\n'` 24.000），连关草稿的冷跑与热跑都不一致，
sha 对照在那个 prompt 上没有判别力。换一个复述型任务：调用体几乎是照抄，平手少。

## 预期（跑之前写）
- E1 kv16：关草稿冷/热一致，开草稿与关草稿（热）sha 一致。把握：中。
- E2 kv8：开/关一致。把握：中低（exp12 kv8 的 code 就分叉过）。
- E3 调用体接受率 ≥ 90%（照抄），整体 decode ≥ 1.6×。把握：中。
