# 采样参数：请求里的 temperature / top_p / top_k / min_p / repetition_penalty / stop / seed

> 2026-09-21 SAD 结论（owner 一次拍板四点，"go"）。已实现并合 main（merge 435a74b）。取证 `research/2026-09-21-sampling`（SMP-001..004，exp01/02）。

起因：公开前，OpenAI 兼容 server 最基本的预期；此前这些字段全部被忽略（README "What does not work yet" 第一条）。

## 1. 裁决：名字映射、校验、未知参数
- 收 `temperature`→`temp`、`top_p`、`top_k`、`min_p`、`repetition_penalty`（后三个原样透传）；`stop` 见 §4。
- 范围按 OpenAI：temperature 0–2、top_p (0,1]、top_k ≥ 0 整数、min_p [0,1]、repetition_penalty > 0、stop ≤ 4 条非空串。
  越界回 400，`error.param` 点名字段，message 说规则。布尔不算数字。
- 不认识的参数忽略不报错（OpenAI 同样做法）。
- 落点：`lmk/sampling.py`。

## 2. 裁决：缺省 = 模型作者的设置；lmk 不发明温度
原裁决"请求没给就不传，让引擎用模型自带的 generation_config"。**实测前提不成立**（SMP-001）：引擎缺省 temp 0 = 贪心，
且从不读 `generation_config.json`。故由 lmk 在加载时读那份文件（`temperature`/`top_p`/`top_k`；`do_sample: false` ⇒ temp 0），
作为请求未指定时的值。**行为改变**：lmk 从第一版起一直贪心（THK-001），现在缺省按模型作者的采样（Qwen3.8-27B：1.0 / 0.95 / 20）。
`lmk status`、`lmk up` 多一行显示这组值；`LmkChatDone` 记每次实际生效的 `sampling`。

## 3. 裁决：seed——无法兑现，如实报
原裁决"照引擎的全局语义实现，并发下不保证，README 写明"。**实测前提不成立**（SMP-003）：引擎在批处理路径上忽略 seed
（`generate.py:688`），lmk 的模型正走这条路径。改为：seed 收下、不传引擎、记 `LmkParamIgnored`（不拒绝——客户端库常默认带 seed）；
README 写明不支持，要复现用 `temperature: 0`（exp01：逐字相同）。

被否：报 400 拒绝 seed——会把默认带 seed 的客户端整个挡在门外。

## 4. 裁决：stop 只对回答段生效
原裁决留待实测。exp01：交给引擎的 `stop_strings` 对整条 token 流生效，思考型模型在思考段第 12 个 token 就命中、回答为空。
故 **stop 不传引擎**，lmk 在自己的输出切分器之后、只对回答段匹配（`lmk/stopmatch.py`），命中即用取消路径现成的
`generation.pieces.close()` 关引擎生成器；停止串本身不进输出；跨 piece 的匹配靠留一段尾巴（最长停止串减一）。
exp02：同一请求思考完整跑完（262 token）、回答在停止串前截住，流式与非流式一致。代价：命中前引擎可能多算几个 token。

被否：把 stop 交给引擎并在文档里写"思考里也会停"——那等于让思考型模型上的 stop 不可用。

## 5. 不做（另开题）
`response_format` / `json_schema`：引擎有 `json_schema` 参数，与思考段和工具调用的关系没想清楚。
